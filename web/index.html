How it works

  1. 1

    Normalise symptoms

    About 220 lay phrases map to 131 medical symptom terms: "throwing up" becomes vomiting and "tummy ache" becomes stomach pain. "No fever" is marked as negated.

  2. 2

    Vectorise

    Porter-stemmed tokens become TF-IDF features: 7,427 word uni/bi-grams and 8,604 character n-grams, with sublinear term frequency.

  3. 3

    Classify

    A LinearSVC with sigmoid calibration turns the features into a probability for each of the 41 diseases.

  4. 4

    Ask, then answer

    Below 90% confidence, the bot asks about the symptom that best separates the top candidates. Each answer updates the probabilities with Bayes' rule.

5-fold cross-validation on natural language: 97.5% ± 0.3%. Structured and lay-language sentences are template-generated, so the natural-language score is the most realistic number.

Engineering highlights

  • 64% lower latency than the first version (5.19 → 1.89 ms per message) at the same accuracy, from pruned features and a single calibrated model
  • Follow-up questions raise top-1 accuracy from 71.7% to 86.8% when users mention only two symptoms
  • No data leakage: 4,616 duplicate rows removed before splitting
  • Browser port verified against the Python model: identical outputs on 344 texts and 13 full conversations
